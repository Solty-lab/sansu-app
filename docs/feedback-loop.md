# フィードバックと改善の進め方

## ページ
- 娘さん用: `index.html` (練習・じぶんの記録)。フッターに保護者ページへの小さなリンク。
- 保護者用: `parent.html` (きろく・フィードバック・改善の記録)。記録は読むだけ (リセットのときだけ書く)。
- 確認用 artifact: `dist/keisan-tani.html` (両方入り)。
- `sh src/build.sh` で3つを作る。`PAGE` 定数 ('child' | 'parent' | 'all') で画面が切りかわる。

## 声の集め方 (アプリ内)
| どこで | 種類 (kind) | 中身 |
|---|---|---|
| 説明・読みものの各ページ | frame | わかった / わからない、問題・何枚目・説明文の頭 |
| 答えたあと「この問題について おしえて」 | problem | 答えがおかしい / 意味がわからない / 図が見にくい / むずかしすぎる |
| 結果画面 | session, comment | かんたん / ちょうどいい / むずかしい、ひとこと |
| じぶんの記録 | idea | おねがい・アイデア |

記録は端末の localStorage (`keisan-tani-v1` の `feedback`)。保護者の端末へは「記録を おくる」(JSON ファイル、AirDrop など) → 保護者ページで読みこみ (`keisan-parent-v1` の `imports`)。

## Claude への送り方
保護者ページ「フィードバック → まとめを作る」で番号つき (FB-YYYYMMDD-n) のまとめを作り、プロジェクトのスレッドにはりつける。送ったら「送信済み」にする。
まとめの中身: 保護者のメモ [N…]、娘さんの声 [F…]、記録から自動で見つけたこと (正答率が低い・しくみ先見が多い・時間がかかる・「わからない」が多い説明・「むずかしい」が多い練習)、数字。

## Claude の対応手順
1. まとめの各項目を「直す / 様子を見る / 対応しない (理由)」に分ける。[N][F] 番号で返事する。
2. 直したら `src/changelog.js` の先頭に版を追加し、`from` にまとめの番号 (FB-…) を入れる。→ 保護者ページ「改善の記録」で「対応 v…」と表示される。
3. `node src/test.js && node src/test2.js && node src/test3.js` → `sh src/build.sh` → main に push (GitHub Pages)。確認用 artifact も更新。
4. シナリオ (/mnt/project-files/scenario/) に版の変更を追記。

## 注意
- リポジトリは公開なので、娘さんの声や記録を Issue やコミットに書かない (まとめはスレッドだけ)。
- 消費税・為替・利率は例の数字。制度が変わったら `MONEY_FACTS` (src/logic.js) を直す。
